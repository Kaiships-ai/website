## Read this first

Sonnet 5.5 came out on 28 Sep 2026, and the question I keep getting is simple: which Claude do I use for what?

This is the short answer: a table by task, three rules to stop burning your limits, and the numbers from Anthropic's launch page, including the places where Sonnet loses.

Before you switch to a bigger model, change the effort setting. Anthropic's own model guide says tuning effort is often a better lever than switching models. Most people jump to the biggest model first and pay for it.

## The short version

Checked against Anthropic's model guide on 6 Oct 2026.

| Your task | Use | Why |
| --- | --- | --- |
| Everyday coding: fix a bug, add a small feature, write a script | Sonnet 5.5 | Fast, and listed for everyday coding |
| Data analysis, content creation | Sonnet 5.5 | Listed for these in Anthropic's guide |
| Big refactor, complex system, hours-long autonomous coding | Opus 5.5 | Built for complex agentic coding |
| Computer use and vision-heavy workflows | Opus 5.5 | Anthropic's pick for these |
| Hours-long agent sessions, deep research that ends in a finished doc or deck | Fable 5.1 | Highest capability |
| Sub-agents, high-volume simple jobs, real-time apps | Haiku 4.5 | Lowest latency and price |

## Three rules that save your limits

1. Default to Sonnet 5.5 for everyday work. Move up to Opus 5.5 only when the task is big and messy. This is my habit, not Anthropic's rule. Their guide says most workloads can start with Opus 5.5, so test it on your own prompts.
2. Change the effort setting before you change the model.
3. Mix models. Let a cheap model do the work (Haiku or Sonnet as workers) and a stronger one plan and review (Opus as the orchestrator). Anthropic describes this orchestrator and workers pattern in its model guide.

## What changed with Sonnet 5.5

These are Anthropic's own numbers from its launch page: https://www.anthropic.com/claude-sonnet-5-5

- Terminal-Bench 4.0 (a coding test): Sonnet 5.5 70.6%, Opus 5.5 66.4%, Sonnet 5 10.3%.
- Speed: writes output 30%+ faster than Sonnet 5.
- Cost: up to 30% less per task, because it needs fewer tokens. The price per token is $2 per million input and $10 per million output.
- Pokémon Red: the first Sonnet model to beat it working only from screenshots.

## What doesn't work

Sonnet 5.5 does not beat Opus 5.5 everywhere. On Anthropic's other listed coding tests Opus 5.5 is still ahead: FrontierCode 1.1 (54.4% vs 46.2%, Sonnet at max effort) and CursorBench 4.0 (57.8% vs 55.5%).

These are Anthropic's numbers on Anthropic's tests. They tell you where to start, not what is best for your code. Test with your own prompts.

Sources: https://platform.claude.com/docs/en/about-claude/models/choosing-a-model

## If you only do three things

1. Start everyday coding on Sonnet 5.5, and keep Opus 5.5 for big, messy work.
2. When a result is weak, raise the effort setting before you pick a bigger model.
3. Run your own prompts on two models and keep the cheaper one if the result is good enough.
