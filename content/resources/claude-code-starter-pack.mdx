This is the exact baseline I drop onto every new machine before I write a single line for a client or product: one curated `CLAUDE.md`, 18 skills, and 4 agents. It is the anti-slop starter kit - not a prompt list, not a screenshot of settings, but real files you install and read for yourself.

It is for solo builders who opened Claude Code, got a burst of magic, then watched the agent drift, burn tokens, and confidently ship something broken. The PACK is the guardrails I wish I had on day one.

## What you need

- Claude Code installed and authenticated (see the zero-to-shipping guide if not).
- A terminal and a text editor.
- The PACK files - get them on [the Starter PACK page](/pack) (delivered by email, repo link shown instantly).

## Setup

1. Create your global skills and agents folders if they do not exist. Everything Claude Code loads globally lives under `~/.claude`.

<Prompt title="Create the folders">

```text
mkdir -p ~/.claude/skills ~/.claude/agents
```

</Prompt>

2. Copy the 18 skill folders and 4 agent files from the PACK into those directories. Each skill is a folder with a SKILL.md; each agent is a Markdown file with frontmatter. Restart Claude Code so it re-scans.

3. Drop the curated `CLAUDE.md` into your project root. Start from this skeleton and cut anything that does not apply - a short, true CLAUDE.md beats a long, aspirational one.

<Prompt title="CLAUDE.md skeleton (project root)">

```text
# Project: [name]

## What this is
One or two sentences. What we are building and for whom.

## Rules
- Verify before you claim done: run the test or show the output.
- Keep changes small. One task, one diff.
- Never auto-approve deletes, force-push, or secrets access.
- If a step can fail, say so - do not paper over it.

## Stack
List the real versions. Point to the config files, do not restate them.

## Commands
- Build: [command]
- Test: [command]
- Run locally: [command]
```

</Prompt>

4. Verify the install. Ask Claude Code to list what it loaded. If a skill or agent is missing, the folder is in the wrong place or the frontmatter is malformed.

### What each piece does

- **CLAUDE.md** - the standing rules above. Cuts drift and token burn on every turn.
- **Skills (18 folders in `skills/`)** - ai-seo, archify, avoid-ai-writing, brainstorming, caveman, ccpm, code-review-and-quality, code-simplification, content-ideator, copywriting, cro, debugging-and-error-recovery, design-system, systematic-debugging, test-driven-development, ui-ux-pro-max, verification-before-completion, writing-plans.
- **Agents (4 files in `agents/`)** - code-reviewer, debugger, git-workflow-manager, technical-writer.
- **model-routing.md** and **mcp/starter.mcp.json** - which model to use for which job, and a starter MCP config.

## What breaks

<Callout type="warn">
Two failure modes to expect. First, a bloated CLAUDE.md quietly costs you on every request - it is prepended to context each turn, so keep it short and delete stale rules. Second, skills and agents only load from the exact paths above with valid frontmatter; a typo in the folder name or a missing title field means Claude Code silently skips it and you get no error. When something does not load, check the path and the frontmatter first.
</Callout>
