An autonomous coding agent with shell access is exactly as powerful as it sounds, in both directions. Most damage is not dramatic - it is a confident `rm` on the wrong path, a force-push that erases an afternoon, a secret committed to a public repo. This baseline is the boring configuration that stops the boring disasters.

It is for solo builders who let the agent run with some autonomy and want that autonomy fenced. Reading this is a credibility move too: no-slop means you can be trusted with permissions, not just prompts.

## What you need

- Claude Code and its settings file.
- Ten minutes to set permissions before you need them.
- A real secrets store (env vars or a manager), not a text file.

## Setup

1. Set an allow and deny policy. Auto-approve the safe, reversible actions; require a human for the irreversible ones. Configure this in your Claude Code settings.

```json
{
  "permissions": {
    "allow": ["Read", "Edit", "Bash(git status)", "Bash(git diff)"],
    "deny": ["Bash(rm -rf *)", "Bash(git push --force)", "Bash(curl * | sh)"]
  }
}
```

2. Add rules to CLAUDE.md so the intent is stated, not just enforced. Belt and suspenders.

<Prompt title="CLAUDE.md - security rules">
# Never without an explicit go
- Do not delete files or directories - propose the command, let me run it.
- Do not force-push, reset hard, or rewrite history.
- Do not read, print, or commit anything under .env or secrets paths.
- Do not run a command piped from the internet into a shell.
- Do not touch production or deploy without me saying the word.
</Prompt>

3. Quarantine secrets. Keep them in env vars or a manager, and make them uncommittable.

<Prompt title="Keep secrets out of the repo">
echo ".env" >> .gitignore
echo "*.pem" >> .gitignore
echo "secrets/" >> .gitignore
</Prompt>

4. Sandbox risky work. When you let an agent run more freely, do it in a throwaway branch or a container, not on main and not on the only copy of anything you cannot lose.

## What breaks

<Callout type="warn">
The failure is almost always convenience. You get tired of approving prompts, so you widen the allow list, and a week later the agent runs a destructive command you would have stopped. Keep irreversible actions on the human. The second trap is secret leakage: an agent reading a whole directory can pull a key into context and later echo it into a file or a commit - the ignore rules and the do-not-read rule above are what prevent that. Review the allow list monthly; it only ever grows if you let it.
</Callout>
