Your Downloads folder is a graveyard and your Desktop is worse. This agent is the fix, and it doubles as the best first agent you can build: it does something genuinely useful, it is completely safe, and you can see whether it worked by opening a folder. No OAuth, no external system, no risk.

It is for solo builders who want to learn how agents actually work by shipping a small one that earns its keep every day. Start here before you build anything that touches email or money.

## What you need

- Claude Code with an agents folder.
- The folders you want sorted (Downloads, Desktop, screenshots).
- A rough idea of your own filing scheme.

## Setup

1. Define the agent. Move and rename only - never delete. Anything it cannot classify goes to a review folder for you, not to the trash.

<Prompt title="~/.claude/agents/file-organizer.md">

```text
---
name: file-organizer
description: Sort files in a target folder into a clean structure by type and date. Moves and renames only, never deletes.
---

# File organizer

Given a target folder:

1. Group files by type: images, documents, code, archives, installers, media.
2. Move each into a subfolder for its type, then a year-month subfolder by modified date.
3. Rename screenshots to a readable date-time form.
4. Anything you cannot classify goes to a _review folder. Never delete, never overwrite.
5. Report a summary: how many moved, into what, and what landed in _review.
```

</Prompt>

2. Dry-run it first. Ask the agent to list what it would move before it moves anything. Read the plan. This habit - preview, then act - is worth building on your very first agent.

<Prompt title="Preview before acting">

```text
Run the file-organizer on ~/Downloads but only PRINT the planned moves. Do not move anything yet. I will approve.
```

</Prompt>

3. Approve and run for real. Open the folders and check. If the scheme is wrong, fix the rules in the agent file, not the files by hand.

4. Make it a habit. Run it weekly, or wire it into your weekly ship ritual so the machine stays tidy without you thinking about it.

## What breaks

<Callout type="warn">
Low stakes, but two things to watch. Name collisions: two files with the same name headed for the same folder can overwrite each other - the agent above is told never to overwrite, but confirm that on your first real run. Misclassification: it will occasionally guess a file's type wrong, which is exactly why unknowns go to _review instead of being deleted or force-fit. Never give this agent delete permission; a tidy folder is not worth a lost file.
</Callout>
